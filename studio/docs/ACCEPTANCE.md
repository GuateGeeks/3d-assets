# Studio acceptance

Apply the gates separately, using PASS, FAIL, BLOCKED or NOT_RUN. A successful command
or fixture test is not visual, content, rights, provider or GPU approval.

| Gate | Evidence required |
| --- | --- |
| Structure/technical | Record validation, verified input/output hashes, correct coordinates and dimensions, lifecycle/interaction tests; fresh reopen/reimport and clip inspection for exported artifacts |
| Visual | Opened comparable views and critical animation states; camera, viewport and renderer settings recorded; contacts, silhouette and deformation inspected |
| Content | Object/scene performs the intended function; labels, references and educational claims reviewed against the brief |
| Provenance | Author, source and actual license recorded; private/recovered assets remain outside public packages unless authorized |

Interactive modules retain their source, build lock and scene specification. GLB captures
only compatible geometry/materials/animations. Preserve executable behavior separately;
report unsupported shaders/textures/controls explicitly. Analytical pose playback is the
current runtime; no physics engine or arbitrary Arduino interpreter is implied.

For providers, separate account connectivity, fixture tests and an actual generation
receipt. Record transport-specific constraints/costs and task IDs. An uncertain paid
submission is reconciled, not repeated. For rigs, validate anatomy, weights, hierarchy,
rest pose and motion before acceptance; technical inference alone does not approve them.

A package manifest inventories every file by path and SHA-256. Each of technical,
visual, content and provenance references a hashed JSON review with status PASS and
`subjects` mapping every inventoried path to its exact hash. Changed files invalidate
those reviews. `package` refuses missing/stale reviews, private paths, path escapes and
existing output files. Artifact and review bytes are hashed as those exact chunks enter
the archive; a mismatch removes the newly created partial ZIP and preserves any
previous delivery. This mechanism preserves approvals; it does not authenticate a
human reviewer or replace actually performing the review.

The creation-lab canary and six-view Blender checks remain scoped to Blender creation.
The cotizador bridge keeps its own names, rigid rig and triangle budgets. Do not relax
those contracts to fit a new route. Original assets, benchmarks and failures stay intact.
